# QA Case Study: Artyfarty — Art Marketplace Platform

**Project:** Artyfarty  
**Application Type:** Web and Mobile Application  
**Role:** Software Quality Assurance Engineer  
**Testing Focus:** Functional, UI, API, Regression, and Workflow Testing

## 1. Project Overview

Artyfarty is a multi-role art marketplace that connects students with artists for booking art classes across different disciplines and locations. The platform supports artist discovery, scheduling, bookings, payments, and communication through web and mobile experiences.

The platform includes separate experiences for Admins, Artists, and Students, each with different permissions and workflows.

## 2. Key Platform Features

- **Role-Based Access:** Separate Admin, Artist, and Student experiences.
- **Artist Discovery:** Artist profiles, portfolios, map integration, and filtered listings.
- **Class Booking:** Booking workflows, scheduling, and availability management.
- **Payments:** Token-based transactions through Stripe.
- **Student Dashboard:** Booking history and token balance.
- **Artist Management:** Profiles, portfolios, schedules, and availability.
- **Real-Time Communication:** Chat between students and artists.
- **Notifications:** Updates related to bookings and user activity.
- **Ratings and Reviews:** Feedback and artist ranking functionality.
- **Admin Panel:** User management, analytics, and content moderation.

## 3. My QA Responsibilities

### Functional Testing

- Tested key application workflows to verify that features behaved as expected.
- Validated booking and scheduling workflows.
- Checked interactions across the platform's main modules.

### Role-Based Access Testing

- Tested role-specific functionality for Admin, Artist, and Student accounts.
- Checked whether users could access the features appropriate to their assigned roles.
- Validated relevant workflows across the different user experiences.

### Booking and Scheduling Testing

- Tested class booking workflows and related scheduling functionality.
- Checked interactions involving artist availability and student bookings.

### Payment Testing

- Tested payment-related workflows involving the platform's token-based payment functionality.
- Checked expected behavior during payment-related interactions.

### Chat and Notification Testing

- Tested chat functionality between students and artists.
- Validated notification behavior and related user interactions.

### UI and Mobile Application Testing

- Performed UI testing to identify presentation issues and inconsistencies.
- Tested mobile application workflows and user interactions.

### API Testing

- Performed API testing to validate relevant application endpoints and expected behavior.

### Regression Testing

- Rechecked relevant functionality after changes to help identify unintended impacts on existing features.

### Defect Reporting

- Documented identified defects with clear reproduction steps and expected versus actual behavior.
- Communicated issues to support investigation and resolution.

## 4. Testing Approach

My testing activities focused on validating key user journeys, role-specific functionality, and interactions between related modules.

The main areas of coverage included:

1. User access and role-based functionality.
2. Artist discovery and profile interactions.
3. Class booking and scheduling.
4. Payment-related workflows.
5. Chat and notification behavior.
6. Mobile UI and functional behavior.
7. Relevant API responses and application interactions.
8. Regression checks and defect reporting.
